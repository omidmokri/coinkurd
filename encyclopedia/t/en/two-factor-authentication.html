Simple definition

A second proof of identity on top of your password — a code from an app, or a physical key — so a stolen password alone is not enough to get into an account.

Professional definition

An access control requiring two independent factors, typically something you know and something you hold. The common forms rank clearly: a hardware security key is strongest, an authenticator app is next, and SMS codes are weakest, because the phone number itself can be taken over.

Technical definition

SMS codes travel through a channel the user does not control: a carrier can be persuaded to move the number to an attacker's SIM, which defeats SMS 2FA outright. Time-based app codes are generated from a shared secret held on the device and are not exposed to that attack, though they can still be relayed through a convincing fake login page. Hardware keys using FIDO2 bind the response to the site's origin, so a copied page cannot use it. None of this protects a key you hold yourself.

Academic definition

An authentication requirement for two independent factors, whose effective strength is bounded by the weakest channel through which any factor can be recovered, intercepted or replayed.

Mechanism

A second factor helps only if an attacker cannot obtain it by the same route as the first. A password phished on a fake page and a code typed into the same page travel one path, which is why origin-bound hardware keys are stronger: the proof is useless anywhere else. A code sent to a phone number depends on a third party keeping control of that number.

In practice

Who uses it
Everyone holding an exchange, broker, email or domain account, and the operations teams that set account policy for them.
Why it matters
It stops a leaked or reused password from turning directly into account takeover, which is the most common single step in a loss.
Limitations
It protects an account login, not keys you hold yourself, and no factor saves an account whose email or phone-based reset path can be captured.

Common mistakes

  • Leaving SMS enabled as a fallback after adding an app or a key.
  • Reading a code aloud to anyone who contacts you claiming to be support.
  • Enabling it without storing the recovery codes offline first.

Examples

security

Two accounts, same password leak. The one with SMS codes falls when the attacker takes over the phone number. The one with a hardware key does not, because the key never leaves the owner and answers only to the real domain.

numeric

A six-digit code has one million values and lives for about 30 seconds, so guessing is not the threat. The realistic attack is getting you to hand the code over, or taking the channel it arrives on.

Given
  • Code length = 6 decimal digits
  • Validity window = 30 seconds
  • Server applies rate limiting on failed attempts
Steps
  1. Possible codes = 10^6 = 1,000,000
  2. With rate limiting, attempts available inside 30 seconds are a tiny fraction of that space
Guessing is negligible; interception and social engineering are the real paths

The arithmetic is about brute force only. It says nothing about SMS interception, which bypasses the code space entirely by taking the delivery channel.

Commonly confused with

Self-Custody

Two-factor authentication guards a login at a service. It has no effect on a blockchain transaction signed with your own key, which needs no account at all.
