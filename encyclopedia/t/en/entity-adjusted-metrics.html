Entity-Adjusted Metrics

Simple definition

On-chain figures recalculated so that moves between a holder's own addresses no longer count. It strips out shuffling that looks like activity but is not.

Professional definition

Metrics computed over inferred entities rather than raw addresses, with transfers internal to one entity removed. Adjusted transfer volume and entity counts are the common cases, and they are typically a fraction of the unadjusted figures.

Technical definition

A second layer built on an address clustering. Raw on-chain aggregates count every ledger movement, including exchange-internal consolidation, wallet reorganisation and change outputs, all of which inflate volume and address counts without any economic transfer. Adjusted series net these out. The adjustment inherits every error in the underlying clustering, so the series is a provider's model output and not a measurement from the chain, and two providers can report materially different adjusted figures for the same block range.

Academic definition

On-chain aggregates recomputed over an inferred entity partition, netting out intra-entity transfers so that reported activity approximates economically distinct transfers.

Mechanism

A ledger records movements of coins, not transfers of economic interest, and the two diverge whenever one party moves funds between its own addresses. Large custodians do this constantly for operational reasons, so raw aggregates are dominated by internal bookkeeping. Netting it out requires knowing which addresses share an owner, and that knowledge is itself inferred, so the correction is an estimate applied on top of an estimate.

In practice

Who uses it
Analysts using on-chain activity series, data providers publishing them, and researchers who need an activity measure that is not dominated by internal transfers.
Why it matters
Unadjusted volume and address counts can be dominated by internal movement, so an adjusted series is usually the only version worth comparing over time.
Limitations
The series inherits all clustering error and each provider's undisclosed rules, so adjusted figures are not comparable across providers and are not measurements of the chain.

Common mistakes

  • Comparing one provider's adjusted volume with another's raw volume.
  • Treating entity counts as user counts.
  • Citing an adjusted figure without naming the provider and method.

Examples

numeric

In an illustrative window, raw transfer volume is 10.0 units and 6.2 of that is between addresses attributed to the same entity. Adjusted volume is 3.8, so 62% of the headline figure was internal bookkeeping.

Given
  • raw transfer volume V_raw = 10.0 (illustrative units, not an observation)
  • volume attributed to intra-entity transfers V_int = 6.2
  • entity partition supplied by a clustering model
Steps
  1. V_adj = 10.0 - 6.2 = 3.8
  2. share removed = 6.2 / 10.0 = 0.62
adjusted volume 3.8, with 62% of raw volume removed

The split depends entirely on the clustering. A clustering that merged two exchanges would classify genuine transfers between them as internal and understate adjusted volume.

crypto

A custodian reorganises its cold storage and moves large balances between its own addresses. Raw volume spikes and headlines report heavy on-chain activity; the adjusted series barely moves, because no economic transfer occurred.

Mathematical foundation

V^{\text{adj}}_t = V^{\text{raw}}_t - V^{\text{int}}_t

Variables

Procedure

Build or obtain an address clustering. Label each transfer as internal or external by comparing the sender's and receiver's assigned entities. Subtract the internal total from the raw total for each period. Publish the clustering version alongside the series, since changing the clustering changes the history.

Worked example

Given
  • V_raw = 10.0 illustrative units
  • V_int = 6.2 illustrative units
Steps
  1. V_adj = 10.0 - 6.2
V_adj = 3.8, a 62% reduction

Interpretation

The adjusted figure is an attempt to count economically distinct transfers rather than ledger events. It is better suited to that question than the raw figure, and it is still a model output whose level depends on who did the clustering.

Assumptions

  • An entity partition over addresses exists and is correct enough to classify transfers; this is exactly what address clustering can only estimate.
  • Providers define entities and the internal set differently. Some also exclude change outputs, dust or exchange-internal hops separately, so the same identity can produce different adjusted series.
  • The subtraction is stated here as the general form; this encyclopedia's registry documents entity-level metric construction only at the level of a provider's own guides, not as a standardised definition.
Limits of the formula
  • Every clustering error propagates: a false merge removes genuine transfers as internal, while a missed link leaves internal shuffling in the series.
  • Historical values can be restated when a provider updates its clustering, so an adjusted series is not a fixed record and should always be cited with its source and version.

Commonly confused with

Transaction Count

Transaction count is read directly off the chain and is reproducible by anyone running a node. An entity-adjusted figure requires an ownership model, so two analysts with the same blocks can legitimately report different numbers.
