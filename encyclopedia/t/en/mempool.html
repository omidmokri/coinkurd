Simple definition

Each node's waiting area for transactions that have been broadcast but not yet put in a block. When it is crowded, the ones offering the lowest fee wait longest.

Professional definition

A node-local set of validated but unconfirmed transactions. There is no single global mempool: every node applies its own acceptance policy, size cap and eviction rule, so two nodes can hold different pending sets. Block producers select from their own view, normally ranking by fee per unit of size.

Technical definition

Selection is by fee rate rather than absolute fee, because block space is the scarce resource. Replacement and package rules let a sender or a dependent raise effective fee rate after broadcast. When the pool's cap binds, the lowest-rate entries are evicted and must be rebroadcast. Private order flow and builder bundles bypass the public pool entirely, so public mempool depth increasingly understates real demand for inclusion.

Academic definition

The set of validated, unconfirmed transactions retained in a node's local memory pending block inclusion; its contents are a function of node policy and propagation rather than a property of the ledger itself.

Mechanism

Block space is auctioned implicitly: producers maximise revenue by packing the highest fee rates into a limited block, so position in the queue is bought, not earned by arrival time. Because each node keeps its own pool and propagation is imperfect, what a public explorer shows is one sample of a fragmented, partly hidden order flow.

In practice

Who uses it
Wallet and node engineers setting fee estimates, exchanges managing withdrawal batches, and searchers and block builders competing for inclusion.
Why it matters
It is where fee competition actually happens, so it governs how long a transaction waits and how much inclusion costs right now.
Limitations
No node sees the whole picture, and private order flow is invisible to all of them. Mempool charts are therefore samples, not censuses.

Common mistakes

  • Treating a transaction visible in the mempool as settled.
  • Reading one explorer's mempool as the network's whole pending set.
  • Setting a fee from yesterday's congestion rather than the next blocks'.

Examples

numeric

A 200 virtual-byte transaction at 10 satoshi per virtual byte pays 2,000 satoshi. Raising the rate to 50 pays 10,000. The transaction did not get bigger; only its position in the fee ranking did.

Given
  • transaction size = 200 virtual bytes
  • low fee rate = 10 satoshi per virtual byte
  • raised fee rate = 50 satoshi per virtual byte
Steps
  1. 200 x 10 = 2,000 satoshi
  2. 200 x 50 = 10,000 satoshi
2,000 satoshi versus 10,000 satoshi for the same transaction

Fee rates are illustrative. Producers rank by rate, so a large transaction at a low rate loses to a small one at a high rate.

crypto

During congestion a low-rate transaction can sit pending for hours, then be evicted when nodes hit their pool cap. It has not failed and has not settled: it simply no longer exists in anyone's queue until rebroadcast.

Commonly confused with

Blockchain

The chain is the settled record; the mempool is the queue in front of it. A transaction in the mempool has been announced and nothing more, and it can still be replaced, dropped or reordered.
