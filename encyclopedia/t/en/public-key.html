Simple definition

The half of a key pair you can safely show anyone. Your address comes from it, and it is what lets others check a signature you produced.

Professional definition

The non-secret element of an asymmetric key pair, computed one-way from the private key and published directly or hashed into an address. Nodes use it to verify that a signature came from the holder of the matching private key, without ever learning that key.

Technical definition

On secp256k1 the public key is the curve point obtained by multiplying the generator by the private scalar; recovering the scalar from the point is the discrete-logarithm problem and is infeasible at these sizes. Bitcoin addresses hash the encoded point; Ethereum addresses take the last twenty bytes of its Keccak-256 hash. Publishing a public key is therefore safe, while publishing the private key transfers control irreversibly.

Academic definition

The public element of an asymmetric key pair, derived by a one-way group operation from the private scalar and sufficient to verify signatures that it cannot itself produce.

Mechanism

Verification and authorisation are deliberately separated. Anyone can check a signature with the public key, but only the private key can produce one, so a network of strangers can agree on ownership with no registrar. That asymmetry is also why a public key or address can be posted openly with no loss of control.

In practice

Who uses it
Anyone receiving funds, wallet and node developers, auditors checking signed messages, and services that whitelist addresses.
Why it matters
It is the identifier you can share: payments, proofs of ownership and address whitelists all work from the public half.
Limitations
A public key or address is not secret information, but reusing one across contexts links your activity and exposes a transaction history.

Common mistakes

  • Confusing the public key with the private key when exporting a wallet.
  • Assuming a published address keeps your balance private.
  • Trusting an address someone sent you without confirming it with them.

Examples

everyday

A letterbox and its key: the slot can be shown to the whole street, the key cannot. Anyone may post a letter; only the keyholder can empty the box.

numeric

An uncompressed secp256k1 public key is 65 bytes and a compressed one 33. An Ethereum address keeps the last 20 bytes of the Keccak-256 hash of the 64-byte point: the 40 hex characters you copy.

Given
  • Uncompressed point = 1-byte prefix + 32-byte x + 32-byte y = 65 bytes
  • Compressed point = 1-byte parity prefix + 32-byte x = 33 bytes
  • Ethereum address = last 20 bytes of Keccak-256 over the 64 bytes of x and y
Steps
  1. 65 - 1 = 64 bytes of coordinate data hashed
  2. 20 bytes written in hexadecimal = 40 characters
33 or 65 bytes of public key; a 20-byte, 40-character address

These are encoding facts for secp256k1 chains. Other curves and address formats differ, and Keccak-256 is not one of the SHA-2 functions standardised in FIPS 180-4.

Private Key
