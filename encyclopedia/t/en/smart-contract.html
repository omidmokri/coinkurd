Simple definition

A program stored on a blockchain. When someone sends it a transaction it runs the same way for everyone, and nobody can stop it half-way or change the result afterwards.

Professional definition

Deployed code with its own address and persistent state, executed by every node as part of validating a block. It can hold balances, enforce conditions and call other contracts, so it replaces a trusted operator with published logic — and inherits every bug in that logic.

Technical definition

Deterministic bytecode run by the network's virtual machine, metered by gas and committed to state only if execution completes within the limit. Determinism rules out direct access to off-chain data, so external facts arrive through oracles, and a contract cannot schedule itself: it acts only when called. Immutability is a property of deployed bytecode, not of the system; proxy patterns and admin keys let the behaviour behind an address change, which is a governance fact rather than a technical detail.

Academic definition

A deterministic program whose code and state reside on a distributed ledger and whose execution is replicated and verified by consensus, enabling conditional transfers without a trusted intermediary.

Mechanism

Because every node re-executes the same code on the same inputs, the outcome needs no arbiter — the network agrees on it the way it agrees on a transfer. That removes discretion in both directions: a contract will not be talked into an exception for a sympathetic user, and it will not refuse an attacker whose call is valid under the code as written.

In practice

Who uses it
Protocol developers, auditors, DeFi users signing approvals, and anyone evaluating a token or a vault.
Why it matters
It is where custody, pricing and permissions actually live on-chain, so contract behaviour decides what can be taken and by whom.
Limitations
Code enforces what it says, not what the documentation says. Audits reduce risk without removing it, and upgrade or admin keys can change the rules after a user has committed funds.

Common mistakes

  • Reading a project's description instead of what its contract permits.
  • Granting an unlimited token allowance and leaving it in place.
  • Treating an audit report as proof that funds are safe.

Examples

everyday

A vending machine takes a coin and releases the item with no clerk, no judgement and no appeal. It also cannot tell that your coin was pushed in by a stranger. Published logic and no discretion, both ways.

crypto

A lending contract will liquidate a position the moment the price feed crosses the threshold, including when the feed itself is briefly wrong. Nothing in the code distinguishes a real move from a bad oracle update.

Commonly confused with

Honeypot

A smart contract is the technology. A honeypot is one dishonest use of it, where the code is written so that selling fails.
