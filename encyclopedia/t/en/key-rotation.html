Simple definition

Replacing a key with a new one and moving the balance across. A blockchain key cannot be cancelled, so rotation means moving funds, not resetting a password.

Professional definition

Generating a fresh key or seed and migrating control to it — after a suspected exposure, a staff change, a device replacement, or on a schedule. Because an on-chain key cannot be revoked, rotation is an asset and authority transfer: the old key stays valid forever over anything left behind.

Technical definition

Rotation must cover everything the old secret can still reach: all addresses derived from that seed, every contract where the old address is an owner or signer, standing token allowances, exchange API keys and withdrawal whitelists, and every backup copy of the old phrase, which has to be destroyed or the risk is reinstated. Hierarchical derivation makes fresh addresses cheap but does not help after a seed exposure, since the whole tree descends from it. A once-exposed key is permanently unsafe, however long nothing happens.

Academic definition

The controlled replacement of signing material and migration of all authorisations that depend on it, made necessary by the non-revocability of public-key identities on an append-only ledger.

Mechanism

There is no registry to revoke a key, so the only way to invalidate one is to leave it controlling nothing. Any asset, role or allowance the old key can still reach stays at risk indefinitely, which makes rotation an inventory problem first and a cryptography problem second.

In practice

Who uses it
Operations and treasury teams, validators, bot and API operators, and any holder who suspects a device or phrase was exposed.
Why it matters
It bounds the damage of an exposure that cannot be undone, and keeps signer lists matching who should actually hold them.
Limitations
Rotation costs fees and downtime, and it is only as complete as the inventory of places the old key is referenced. It cannot recover what has already moved.

Common mistakes

  • Moving funds back to a key that was once exposed.
  • Rotating the wallet but leaving the old address as a contract owner or signer.
  • Keeping the old recovery phrase after migrating.

Examples

numeric

One exposed seed covers 11 funded addresses on 4 chains, 2 multisig signer slots, 3 exchange API keys and 6 live token allowances: 22 items to migrate or revoke. A rotation that misses one is not a rotation.

Given
  • Funded addresses from the exposed seed = 11
  • Signer slots held by those addresses = 2
  • Exchange API keys tied to the same operation = 3
  • Live token allowances granted from those addresses = 6

22 separate actions, each needed before the rotation is complete

The inventory is the hard part, not the key generation. Allowances and signer roles are the items most often forgotten, and either one keeps the exposure alive.

security

A laptop running a hot wallet is compromised. Order of work: generate new keys on a clean device, move balances, revoke the old allowances, replace signer roles and API keys, then destroy the old backups.

Commonly confused with

Seed Phrase

Deriving a new address from the same seed is not rotation. If the seed was exposed, every address under it is exposed, however new.

Editorial status

Needs expert reviewindustry-conventionv1.02026-11-05

Flagged by the editor as uncertain on a linguistic, mathematical or regulatory point.

No rotation schedule is recommended: periodic rotation of a cold key carries its own handling risk, and the registry holds no custody standard that prescribes an interval. The statement that a once-exposed key is permanently unsafe is deliberate and must not be softened. The derivation point — a new address from an exposed seed is not a new key — follows directly from BIP-32 and is the most common misunderstanding this entry exists to correct.
