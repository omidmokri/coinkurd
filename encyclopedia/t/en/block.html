Simple definition

A batch of transactions recorded together, stamped with a reference to the block before it. Blocks are the steps by which a chain grows.

Professional definition

The unit of commitment in a chain: an ordered set of transactions plus a header holding the previous block's hash, a commitment to the transaction set, a timestamp and consensus-specific fields. Validity is all-or-nothing — a block is accepted or rejected whole.

Technical definition

A container with two parts. The header is the object consensus acts on: it links to the parent by hash, commits to the body through a Merkle root, and carries the fields the consensus rule checks, such as a timestamp and, under proof of work, a target and a nonce. The body is the transaction list. Because the header commits to the body, changing one transaction changes the header, and therefore every descendant header.

Academic definition

A sequenced batch of state transitions bound to its predecessor by a hash reference and to its contents by a vector commitment, forming the atomic unit of agreement in a replicated ledger.

Mechanism

Batching exists because agreement is expensive: nodes converge once per block rather than once per transaction. The header carries the load. It is small enough to relay and check cheaply, yet commits to the whole body, so a node can verify the chain's shape before downloading a single transaction.

In practice

Who uses it
Protocol engineers, node operators, block-explorer builders, and analysts who count confirmations or measure throughput.
Why it matters
It is the quantum of settlement: a transaction has no on-chain status until a valid block includes it, and depth is counted in blocks.
Limitations
Inclusion in a block is not finality. A block at the tip can be orphaned if a competing branch wins, taking its transactions back to pending.

Common mistakes

  • Treating a broadcast transaction as settled before any block includes it.
  • Reading block size as throughput while ignoring per-transaction weight.
  • Assuming one confirmation means the same thing on every chain.

Examples

crypto

A fee-paying transaction sits in the mempool until a block producer selects it. Raising the fee does not speed up the block; it only improves the odds of being chosen for the next one.

numeric

Suppose a chain fits 2,500 transactions in a block and produces one block every 600 seconds. Sustained throughput is about 4.2 transactions per second — a capacity ceiling set by block size and interval together, not by either alone.

Given
  • transactions per block = 2,500 (illustrative, not a protocol constant)
  • block interval = 600 s
Steps
  1. throughput = 2500 / 600
  2. = 4.166... transactions per second
about 4.2 transactions per second

Illustrative arithmetic. Real chains cap blocks by bytes or gas, so transaction count per block varies with transaction size.

Commonly confused with

Block Height

The block is the container of transactions. The height is that container's position in the chain, counted from the first block.
