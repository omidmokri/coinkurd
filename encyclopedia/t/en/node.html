Simple definition

A computer running the chain's software, connected to others, checking what it is told and passing it on.

Professional definition

A participant in the peer-to-peer network that stores some part of the chain, validates according to its configuration, relays transactions and blocks, and answers queries. Node types differ in what they keep and how much they verify for themselves.

Technical definition

A node is defined by what it checks, not by what it owns. A validating node applies the full rule set to every block and therefore holds an independent opinion of the canonical chain; a non-validating client inherits someone else's opinion. Nodes do not vote: they enforce rules locally and refuse to relay what fails. Block production is a separate role, which is why counting nodes measures reach, not consensus power.

Academic definition

A networked process implementing a chain's peer protocol, maintaining some view of ledger state and applying a locally configured subset of validation rules to the data it receives.

Mechanism

The network has no centre, so correctness is a local property repeated many times: each validating node rejects invalid data on its own, and invalid blocks simply fail to spread. This is also why implementation diversity matters — if nearly everyone runs one client, a bug in that client becomes, in practice, the network's rule.

In practice

Who uses it
Exchanges, custodians, wallet backends, block producers needing a local view, and researchers pulling raw chain data.
Why it matters
Running your own node replaces trusting a third party's answer about your balance, a transaction's status or which chain is the real one.
Limitations
A node reports what the rules say, not what is true off-chain. Bandwidth, storage and pruning choices all limit what a given node can answer.

Common mistakes

  • Counting reachable nodes as a measure of decentralised control.
  • Calling a hosted API endpoint a node.
  • Assuming a wallet pointed at a provider validates anything itself.

Examples

crypto

An exchange credits deposits only from its own validating node. If a provider's endpoint reported a block the exchange's node rejects, the deposit is not credited — the node, not the provider, is the source of truth.

everyday

Think of a hall where every listener holds the same rulebook. A speaker who breaks a rule is simply not repeated onward. Nobody has to vote, and nobody has to be in charge.
