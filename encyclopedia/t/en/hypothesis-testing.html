Hypothesis Testing

Simple definition

A procedure for asking whether a result could plausibly have come from luck alone. It can reject a boring explanation; it cannot prove an interesting one.

Professional definition

A decision rule that assumes a null hypothesis, computes how extreme the observed data would be under it, and rejects the null when that extremity passes a threshold chosen in advance. The threshold controls the long-run rate of false rejections, not the truth of any single conclusion.

Technical definition

A test fixes a null hypothesis, a test statistic with a known distribution under that null, and a significance level alpha that bounds the probability of a type I error. Rejecting the null is not evidence for any particular alternative, and failing to reject is not evidence that the null is true — it may simply mean the sample lacked power. The alpha guarantee holds per test, so it dissolves as soon as many tests are run on the same data.

Academic definition

A frequentist decision procedure that controls the probability of incorrectly rejecting a specified null hypothesis at a pre-chosen level, conditional on the null's sampling distribution.

Mechanism

The logic is one-directional: it computes the probability of the data given the null, never the probability of the null given the data. That asymmetry is what makes the method safe to use and easy to misquote. A five percent level means one in twenty true nulls are rejected by chance, so twenty searches produce a false positive more often than not.

In practice

Who uses it
Strategy researchers, factor analysts, risk teams validating a model, and anyone deciding whether a backtest result is worth capital.
Why it matters
It imposes a discipline: state the boring explanation first, then show the data is hard to square with it. Without that step a profitable backtest and a lucky backtest look identical.
Limitations
The guarantee is per test. Searching strategies until one passes is the multiple-comparisons problem, and the published test statistic then has no valid interpretation at all.

Common mistakes

  • Treating rejection of the null as proof the strategy works.
  • Reading a non-rejection as evidence of no effect.
  • Running dozens of specifications and reporting only the one that passed.

Examples

numeric

A strategy averages 0.05% a day with 1.0% daily standard deviation over 250 days. The standard error is 0.063%, so the t statistic is 0.79 and the two-sided p value about 0.43. The null of zero mean return is not rejected.

Given
  • sample mean daily return = 0.05%
  • sample standard deviation = 1.0%
  • n = 250, so df = 249
  • null hypothesis: true mean = 0
  • returns assumed independent and identically distributed
Steps
  1. standard error = 1.0 / sqrt(250) = 0.063246%
  2. t = 0.05 / 0.063246 = 0.7906
  3. two-sided p from the t distribution with 249 df = 0.4299
t = 0.79, p = 0.43; the null is not rejected at any conventional level

Verified numerically. Not rejecting does not mean the edge is zero. A true daily edge of 0.05% against a 1.0% standard deviation reaches the 5% threshold only around n = 1,540 on average, and is detected with 80% probability only around n = 3,140.

market

A researcher tests twenty unrelated rules at the 5% level. Even if every rule is worthless, the chance that at least one passes is 64%. At a hundred rules it is 99.4%. The winner is then a selection artefact, not a discovery.

Procedure

State the null and the alternative before looking at the result. Choose alpha in advance. Compute the test statistic and its p value under the null. Compare and decide. Then report every test that was run, not only the one that passed, and if many were run adjust the threshold or treat the result as exploratory rather than confirmed.

Worked example

Given
  • sample mean = 0.05% per day
  • s = 1.0% per day
  • n = 250
  • H0: true mean = 0, two-sided, alpha = 0.05
Steps
  1. standard error = 1.0/sqrt(250) = 0.063246
  2. t = 0.05/0.063246 = 0.7906
  3. p with 249 degrees of freedom = 0.4299
  4. 0.4299 > 0.05
Do not reject H0. The observed mean is well inside what a zero-edge strategy produces by chance over 250 days.

Interpretation

A rejection says the data would be unusual if the null were true. It does not say the null is false with any stated probability, and it says nothing about which alternative holds. A non-rejection says the sample could not distinguish the null from the alternatives — absence of evidence, not evidence of absence.

Assumptions

  • The test statistic's distribution under the null must be correct; the t form shown assumes independent, identically distributed observations, which autocorrelated and volatility-clustered return series violate.
  • Alpha must be fixed before the data are examined, and the null must be stated before the result is seen.
  • The stated error rate applies to a single pre-specified test. Under many tests on the same data the family-wise rate is far higher and must be controlled explicitly.
Limits of the formula
  • It cannot assign a probability to a hypothesis. That requires a prior and a Bayesian framework, which is a different procedure answering a different question.
  • Statistical significance is not economic significance: a tiny edge can be significant on a long sample and still vanish under transaction costs.

Commonly confused with

p-value

The test is the whole procedure, including the threshold chosen in advance. The p value is one number the procedure produces, and quoting it alone hides how many tests were run.
