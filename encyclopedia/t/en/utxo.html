Simple definition

A leftover chunk from a past transaction, spendable only as a whole. You do not hold a balance; you hold a set of these chunks.

Professional definition

The unspent-output model: every transaction consumes whole outputs as inputs and creates new outputs, so a wallet's balance is just the sum of outputs it can sign for. Change is an output back to yourself, and validation is checking that each input exists, is unspent and is authorised.

Technical definition

State is a set, not a table of balances. Validity requires every input to reference an existing unspent output and satisfy its spending condition, with the sum of inputs at least the sum of outputs; the difference is the fee. Because outputs are independent, validation parallelises well and local ownership proofs are simple, but there is no global account identity, which makes some contract patterns awkward and complicates reasoning about a single logical owner.

Academic definition

A ledger representation in which state consists of the set of unspent transaction outputs, each consumed atomically by a later transaction that creates new outputs.

Mechanism

Spending whole outputs is what makes double-spending cheap to detect: an input either points at something still in the set or it does not, and no balance arithmetic is needed. The costs are granularity and privacy — wallets accumulate small outputs that cost fees to consolidate, and change outputs link transactions to one another.

In practice

Who uses it
Wallet engineers writing coin-selection logic, exchanges managing large output sets, on-chain analysts doing clustering, and auditors tracing flows.
Why it matters
It explains why fees depend on how many outputs you spend rather than only on how much you send, and why consolidation is a deliberate operation.
Limitations
There is no account to query: a wallet's holdings exist only as outputs it can sign for, so accounting must be reconstructed from the set.

Common mistakes

  • Thinking a wallet holds a balance instead of a set of outputs.
  • Ignoring that spending many small outputs inflates the fee.
  • Assuming change outputs are private to the spender.

Examples

numeric

A wallet spends two outputs of 0.6 and 0.5 to send 0.9 with a fee of 0.0002. Inputs total 1.1, so the change output back to the sender is 0.1998 — the ledger has no concept of a partial spend.

Given
  • inputs = 0.6 + 0.5 = 1.1
  • payment output = 0.9
  • fee = 0.0002
Steps
  1. change = 1.1 - 0.9 - 0.0002
  2. change = 0.1998
one payment output of 0.9 and one change output of 0.1998

Units are chain-native amounts, not currency values. The fee is implicit: it is whatever the inputs exceed the outputs by.

crypto

A merchant who received hundreds of tiny payments holds a fragmented set. Moving the total may need hundreds of inputs, and at a high fee level some of those outputs cost more to spend than they are worth.

Mathematical foundation

\sum_{i} v_{in,i} = \sum_{j} v_{out,j} + f

Variables

v_{in,i}Value of the i-th input, a whole unspent output being consumedchain-native units
v_{out,j}Value of the j-th newly created output, including changechain-native units
fFee, defined as the residual between inputs and outputschain-native units

Procedure

Select enough unspent outputs to cover the payment plus the fee. Create the payment output, then a change output for the remainder. The fee is never written down: it is whatever the inputs exceed the outputs by, and anything you forget to return as change is paid to the block producer.

Worked example

Given
  • inputs 0.6 and 0.5
  • payment 0.9
  • fee 0.0002
Steps
  1. sum inputs = 1.1
  2. change = 1.1 - 0.9 - 0.0002 = 0.1998
outputs: 0.9 to the payee and 0.1998 back as change

Interpretation

The identity is exact, not approximate, and it explains the classic costly error: omit the change output and the entire remainder becomes fee. It also shows why fees track input count, since every input adds bytes to the transaction.

Assumptions

  • Written for a UTXO chain with explicit fees as a residual; account-based chains price execution instead, through a gas mechanism.
  • Amounts are in the chain's own units; no currency conversion is implied.
Limits of the formula
  • The identity says nothing about which outputs a wallet should pick: coin selection is an optimisation over fees, privacy and future flexibility.
  • Some protocols add consensus rules, such as minimum output values, that the identity alone does not capture.

Commonly confused with

Account Model

A UTXO chain stores a set of spendable outputs and no balances. An account chain stores balances and a nonce per account, updating them in place. Same ownership idea, different state representation and different contract ergonomics.
