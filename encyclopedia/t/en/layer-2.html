Simple definition

A separate network that handles transactions away from a main blockchain but keeps settling their results back onto it. Users get cheaper and faster transactions while the main chain stays the final record.

Professional definition

A protocol that executes transactions outside the base chain and posts data, and usually a proof, back to it, inheriting the base chain for settlement and data availability. Rollups dominate: optimistic designs rely on a challenge window with fraud proofs, validity designs on succinct cryptographic proofs.

Technical definition

Trust assumptions differ sharply between designs. An optimistic rollup is safe only if at least one honest party watches and can submit a fraud proof inside the window, which makes withdrawal delays a security feature rather than an inconvenience. A validity rollup moves the assumption into its circuit and proof system. In practice most live systems still run a single sequencer with upgrade keys, so censorship, liveness and upgrade risk sit with the operator, not the base chain.

Academic definition

A protocol that executes state transitions off a base chain while deriving settlement, data availability or dispute resolution from it, raising throughput without establishing an independent consensus set.

Mechanism

Costs fall because the expensive resource, space on the base chain, is shared. Thousands of transactions are executed off-chain and summarised in one submission, so each user pays a fraction of one base-layer cost plus cheap local execution. The security that remains is whatever the base chain can still enforce: data must be published, and disputes must be resolvable there.

In practice

Who uses it
Application developers choosing where to deploy, users seeking lower fees, bridge and custody teams assessing withdrawal risk, and researchers comparing designs.
Why it matters
It makes on-chain activity affordable at volumes a base chain cannot process, without asking users to trust a new validator set from scratch.
Limitations
Inherited security is conditional. Sequencer centralisation, upgrade keys, bridge contracts and challenge-window assumptions are where the real risk sits.

Common mistakes

  • Assuming every chain marketed as a layer 2 actually settles to a base chain.
  • Judging a rollup only by its fee, ignoring withdrawal delay and operator control.
  • Treating a bridged asset as the same asset as the original.

Examples

numeric

A rollup posts one batch to the base chain for 0.3 ETH covering 3,000 transfers. The shared settlement cost per user is 0.0001 ETH, before each user's own execution cost on the rollup.

Given
  • batch posting cost on the base chain = 0.3 ETH (illustrative)
  • transfers in the batch = 3,000
Steps
  1. 0.3 / 3,000 = 0.0001 ETH per transfer
0.0001 ETH of base-layer cost per transfer, plus rollup execution

Illustrative figures. The economics depend on batch size, so fees per user rise when activity is thin and the same fixed cost is shared by fewer transactions.

everyday

Drinks at a bar are noted on a tab and settled once at the end. The bar's till sees one payment instead of twelve, and the record of who owed what lived with the bartender until that moment.

Commonly confused with

Altcoin

A layer 2 inherits settlement and data availability from its base chain. An independent chain with its own validator set does not, however similar the marketing sounds, and its failure modes are entirely its own.
