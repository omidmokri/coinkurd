Simple definition

A pair of keys that belong together: one you keep secret, one you can publish. What the secret key signs, the public key can check.

Professional definition

Asymmetric cryptography: a private key plus a public key derived from it by a one-way operation. In blockchains the pair is used for signing and verification rather than for encrypting messages, and an address is usually a hash of the public key.

Technical definition

Security rests on a computational asymmetry: deriving the public key from the private key is cheap, and inverting that derivation is believed infeasible. Bitcoin and Ethereum use elliptic-curve keys on the secp256k1 curve, where the public key is the private scalar multiplied by a fixed generator point. The underlying hard problem — discrete logarithm — is an assumption, not a theorem, and a key is never safer than the randomness that generated it.

Academic definition

A cryptosystem using mathematically linked key pairs in which the public element can be disclosed freely because recovering the private element from it is computationally infeasible under a standard hardness assumption.

Mechanism

One direction of the derivation is easy and the other is not believed to be, so publishing one half of the pair costs nothing. On a chain this replaces account records with mathematics: control of funds is control of a key, which is why a lost key is lost value and a copied key is stolen value.

In practice

Who uses it
Wallet and key-management engineers, custodians, hardware-wallet makers, and anyone designing recovery or signing policy.
Why it matters
It is the foundation of self-custody and of chain verification: users prove control without a registrar, and nodes check that proof without holding any secret.
Limitations
The hardness assumptions are believed, not proved, and implementations fail far more often than the mathematics — weak randomness, reused values and side channels.

Common mistakes

  • Generating a key from a guessable passphrase or weak randomness.
  • Confusing signing with encryption and expecting the chain to hide data.
  • Treating an address as the key rather than a hash of the public key.

Examples

crypto

A hardware wallet shows an address but never releases the private key. It signs inside the device and returns only the signature, so a compromised computer can misstate what is being signed but cannot extract the key.

numeric

A 256-bit key space holds about 1.16 times ten to the 77 values. Guessing a specific key is hopeless; the practical risk is always weak key generation or a leaked backup, never exhaustive search.

  • key length = 256 bits

about 1.16 x 10^77 candidate keys

Mathematical foundation

K = k \times G

Variables

kPrivate key: a scalar drawn uniformly from the valid rangeinteger
GGenerator point fixed by the curve parameterscurve point
KPublic key: the resulting curve pointcurve point

Procedure

Draw k uniformly from the curve's valid range using a cryptographic random source. Compute K as k-fold elliptic-curve addition of the generator point. Publish K, or an address derived by hashing it, and keep k secret forever.

Worked example

Given
  • k = 2 (illustrative only; a real key is a 256-bit integer)
Steps
  1. K = 2G = G + G, computed with elliptic-curve point addition
  2. serialise K as the public key, then hash it to form an address
a curve point K that anyone can use to verify signatures made with k

Interpretation

The multiplication sign is elliptic-curve point multiplication, not ordinary arithmetic, and it has no cheap inverse. That one-way gap is all that separates a published public key from the funds it controls.

Assumptions

  • Written for elliptic-curve systems such as secp256k1; RSA and other families use different one-way operations.
  • k must come from a cryptographically secure random source; biased or reused values have broken real keys.
  • Hardness of the elliptic-curve discrete logarithm problem is assumed, not proved.
Limits of the formula
  • The formula describes key derivation only. It says nothing about how a signature is produced or verified.
  • Quantum algorithms would break this one-way gap; post-quantum migration is an open protocol-design problem rather than a settled answer.

Commonly confused with

Digital Signature

The key pair is the tool. The signature is one product of using it. Blockchains use the pair mainly to sign, not to encrypt anything.
