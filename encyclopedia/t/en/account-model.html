Simple definition

A ledger that keeps a balance for each account and edits it in place, much the way a bank ledger does.

Professional definition

The account-based state model: addresses map to a balance, a sequence number and, for contracts, code and storage. A transaction updates those entries directly, so no specific coins are consumed, and the per-account nonce stops a signed transaction being replayed.

Technical definition

State is a mapping from addresses to account objects, and a block applies its transactions as a deterministic state-transition function over that mapping. Contracts therefore have persistent identity and storage, which is what makes composable smart contracts practical. The cost is ordering and contention: transactions from one sender must execute in nonce order, and shared global state makes parallel validation harder. Account abstraction extends the model so that a contract itself can act as the paying account.

Academic definition

A ledger representation in which state is a mapping from account identifiers to balances, sequence numbers and optional code and storage, updated in place by a deterministic state-transition function.

Mechanism

Keeping state in one mutable mapping is what lets contracts call one another and read shared data: a contract has an address, so it can hold funds and be addressed again later. The price is ordering. Each account's transactions form a strict sequence, so one stuck low nonce blocks everything queued behind it.

In practice

Who uses it
Smart-contract developers, wallet and relayer engineers, exchanges watching deposit addresses, and analysts reading contract state.
Why it matters
It is the model under which smart contracts, token standards and composability work, and under which one deposit address can be monitored as a single account.
Limitations
Per-account ordering and shared global state constrain parallelism, and cross-chain replay must be prevented by chain identifiers rather than by the model itself.

Common mistakes

  • Broadcasting a later transaction while an earlier nonce is still stuck.
  • Assuming a token balance sits in the wallet rather than in the token contract.
  • Reading a balance as proof of control without knowing the key or contract logic.

Examples

crypto

A token balance is a row in the token contract's storage, not an object in your wallet. The wallet holds only a key; what it controls is the right to ask that contract to change its own records.

numeric

An account broadcasts three transactions with nonces 5, 6 and 7. The one at nonce 5 is underpriced and never included, so none of the three executes: strict per-account ordering means zero of three confirm until nonce 5 clears or is replaced.

Given
  • pending nonces 5, 6, 7 from one account
  • nonce 5 is not included by block producers
Steps
  1. execution requires nonces in strict ascending order
  2. 6 and 7 are not executable while 5 is pending
0 of 3 transactions confirm

This ordering rule is why wallets offer a replace-by-fee style resubmission of the stuck nonce rather than a new transaction.

Commonly confused with

UTXO

An account chain stores balances and a nonce per address and edits them in place. A UTXO chain stores a set of spendable outputs and consumes them whole. The ownership idea is the same; the state representation, fee logic and contract ergonomics are not.
