Block Height

Category

Foundation

Simple definition

The number of blocks that came before a given block, starting from the very first one. It is the chain's page number, not its clock.

Professional definition

The position of a block in the canonical chain, counted from the genesis block at zero. A height identifies a block unambiguously only within one canonical chain; after a reorganisation the same height can hold a different block.

Technical definition

An index, not a timestamp. Height increments by one per accepted block, so it measures blocks elapsed rather than time elapsed. Two competing branches can share a height and disagree on its contents, which is why protocols and explorers identify a block by its hash and use height as a convenience. Confirmation depth is derived from height: tip height minus inclusion height, plus one.

Academic definition

The ordinal index of a block within a canonical chain, defined as zero at the genesis block and incremented once per accepted block.

Mechanism

Height works as an identifier only because one branch is canonical at a time. During a reorganisation the tip height can stay the same or even fall while the blocks under it change, so a transaction that had several confirmations can return to the mempool. Depth in blocks, not height itself, is what measures settlement risk.

In practice

Who uses it
Exchange deposit systems, custody operations, on-chain analysts, and anyone writing a crediting rule based on confirmations.
Why it matters
It gives a deterministic, chain-native index for ordering events and for setting how deep a transaction must be before it is treated as settled.
Limitations
A height tells you nothing about elapsed time, and nothing about whether that height's block is the one your counterparty sees.

Common mistakes

  • Converting height differences into time with the target block interval as if it were exact.
  • Identifying a block by height alone across a reorganisation.
  • Crediting a deposit at one confirmation on a low-hashrate chain.

Examples

crypto

A protocol upgrade is scheduled at a stated height rather than a date, so every node switches rules at the same block regardless of how fast blocks happen to arrive.

numeric

A transaction is included at height 1,000,001 and the tip is now 1,000,006. Its depth is six confirmations, because the including block itself counts as the first.

Given
  • inclusion height = 1,000,001
  • tip height = 1,000,006
  • convention: the including block counts as confirmation 1
Steps
  1. C = 1,000,006 - 1,000,001 + 1
  2. C = 6
6 confirmations

Some tools report depth as tip minus inclusion height, giving 5 for the same chain state. Check the convention before wiring a crediting rule.

Mathematical foundation

C = h_{tip} - h_{tx} + 1

Variables

CConfirmation depth of a transactionblocks
h_{tip}Height of the current tip of the canonical chainblock index
h_{tx}Height of the block that included the transactionblock index

Procedure

Read the height of the block containing the transaction, read the height of the tip your own node considers canonical, subtract, and add one if your convention counts the including block as the first confirmation.

Worked example

Given
  • h_tx = 1,000,001
  • h_tip = 1,000,006
Steps
  1. 1,000,006 - 1,000,001 = 5
  2. 5 + 1 = 6
C = 6 confirmations

Interpretation

C counts blocks of work or attestation stacked on top of a transaction. It is a measure of how costly a reversal would now be, not a guarantee that reversal is impossible.

Assumptions

  • Heights are read from one node's canonical chain; two nodes in disagreement will report different depths.
  • The convention that the including block counts as the first confirmation is common but not universal.
Limits of the formula
  • A reorganisation can lower C or remove the transaction entirely.
  • Equal confirmation counts on different chains do not represent equal security, because the cost per block differs.

Commonly confused with

Block Time

Height counts blocks. Block time measures the interval between them. Multiplying one by the other gives an estimate of elapsed time, never an exact one.
