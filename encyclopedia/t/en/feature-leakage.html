Feature Leakage

Simple definition

When the information a model learns from would not have been available at the moment it is supposed to predict. The model is not forecasting; it is reading the answer.

Professional definition

The presence in a model's features, labels or validation scheme of information unavailable at prediction time. It inflates measured performance without any corresponding predictive ability, and the inflation cannot be corrected after the fact: the results are void, not merely optimistic.

Technical definition

A violation of the temporal information boundary between training and prediction. It enters through at least four routes: a target computed from bars after the decision point; scaling statistics estimated over the whole dataset including the test period; labels derived from a window that overlaps the feature window, which correlates training and test observations; and cross-validation that shuffles time-ordered data so future rows train a model tested on the past. Each breaks the assumption that the test set was unseen, so the reported metric no longer estimates out-of-sample performance.

Academic definition

Contamination of a learning procedure by information not in the prediction-time information set, invalidating the out-of-sample interpretation of the resulting performance estimates.

Mechanism

A performance estimate is only meaningful if the test data was genuinely unavailable during fitting. Any path by which test-period information reaches the model, however indirect, makes the estimate a measure of memory rather than of prediction. Because the contamination is in the procedure rather than in the output, no adjustment can repair the number: the experiment has to be rerun with the boundary restored.

In practice

Who uses it
Anyone who fits a model to market data, reviews a backtest, or is asked to approve capital on the strength of a reported metric.
Why it matters
It is the single most common reason a model that tests superbly fails in production, and it is detectable by auditing the pipeline rather than the result.
Limitations
A clean pipeline removes this specific defect only. It does not address selection across many trials, regime change, or costs, each of which can still destroy a genuine edge.

Common mistakes

  • Fitting the scaler on the full series before splitting it.
  • Labelling with a forward window that overlaps the features.
  • Using shuffled k-fold cross-validation on a time series.

Examples

research

A classifier is trained to predict the next day's direction, but one feature is a rolling mean centred on the current bar, so it already contains tomorrow's close. The model looks excellent and has learned nothing.

numeric

Labels use a five-day forward window but are sampled daily, so neighbouring labels share four of five days. A nominal 1,000 samples carry roughly 200 independent observations, and a reported t-statistic of 3.0 is really about 1.34.

Given
  • label horizon h = 5 days
  • sampling interval = 1 day
  • nominal sample size n = 1000
  • simplifying assumption: non-overlapping blocks are independent
Steps
  1. effective independent observations = 1000 / 5 = 200
  2. standard errors scale with 1 / sqrt(n), so they are understated by sqrt(5) = 2.236
  3. corrected t = 3.0 / 2.236 = 1.34
effective sample about 200; corrected t-statistic about 1.34

The block-independence assumption is itself generous. The corrected figure is an upper bound on significance, and the uncorrected one is not a weaker version of the truth but a different quantity.

Commonly confused with

Overfitting

An overfitted model learned real but unrepeatable detail from data it was entitled to see; honest out-of-sample testing exposes it. Leakage means the test itself was contaminated, so the out-of-sample number is not a weaker result but no result at all.
